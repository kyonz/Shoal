# shoal_cloud_identity (Resource)

A cloud role (an AWS IAM role today) that granted workflows and agents in the namespace may use. Each step that uses it gets short-lived credentials; no cloud key is stored. Managed by namespace admins (`cloud-identities:write`).

Maps to `/v1/namespaces/{namespace}/cloud-identities/{name}`. `spec` is written as a plain object (HCL, or `yamldecode(file(...))`) and uses the same fields as the `spec` of the YAML resource.

## Example Usage

```terraform
resource "shoal_cloud_identity" "aws_prod" {
  name = "aws-prod"
  spec = {
    provider = "aws"
    trust    = "web_identity"
    aws = {
      role_arn = "arn:aws:iam::123456789012:role/shoal-deploy"
      region   = "eu-west-1"
      duration = "1h"
    }
    allow = {
      workflows = ["deploy-*"]
      agents    = ["infra"]
    }
  }
}
```

## `spec` fields

A cloud role a namespace brings to Shoal, and which workflows and agents may use it (§7.1).

At run time Shoal exchanges a credential that starts from its own deployment for short-lived
credentials of the role, scoped to one step attempt and attributed to the run and its initiator.

These are the top-level fields of the CloudIdentity spec, the same as `spec:` in YAML. Nested objects are described in the
server's JSON Schema at `GET /v1/schemas` (also used by the UI builder for validation).
