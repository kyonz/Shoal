# shoal_target_list (Resource)

A target list: a named set of targets (such as the repositories a team owns) given as items, a saved integration query, or items looked up through the query. Campaigns use it with `targets = { list = "name" }`; trigger filters read its keys as `lists['name']`.

Maps to `/v1/namespaces/{namespace}/target-lists/{name}`. `spec` is written as a plain object (HCL, or `yamldecode(file(...))`) and uses the same fields as the `spec` of the YAML resource.

## Example Usage

```terraform
resource "shoal_target_list" "core_repos" {
  name = "core-repos"
  spec = {
    connection = "github-acme"
    resource   = "repository"
    filter     = { org = "acme", archived = false }
    key        = "{{ target.full_name }}"
    items      = [{ full_name = "acme/api" }, { full_name = "acme/web" }]
  }
}

resource "shoal_campaign" "core_uplift" {
  name = "core-uplift"
  spec = {
    workflow = "repo-uplift"
    targets  = { list = shoal_target_list.core_repos.name }
    inputs   = { repo = "{{ target.full_name }}", goal = "Upgrade to Python 3.13" }
  }
}
```

## `spec` fields

A reusable, named set of targets (e.g. repositories) for campaigns and trigger filters.

- ``items`` alone: exactly these targets, as written.
- ``connection`` + ``resource`` alone: a saved query, resolved each time it is used.
- both: exactly the listed targets, each looked up through the query so it carries the
  integration's details (a listed target the query does not return is reported missing).

These are the top-level fields of the TargetList spec, the same as `spec:` in YAML. Nested objects are described in the
server's JSON Schema at `GET /v1/schemas` (also used by the UI builder for validation).
